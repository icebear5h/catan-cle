# Qwen3.8 27B: Piece Recognition and Text-Format Evaluation

Date: 2026-08-16

## Goal

Separate three possible bottlenecks in the 24/110 full-board visual result:

1. recognizing Catan art and pieces;
2. locating/binding visible objects on a dense board;
3. reasoning over an authoritative symbolic state.

The evaluation was staged accordingly: isolated/local visual crops first, then the same 110 full-board questions with vision removed and the board facts rendered in four information-equivalent text formats.

## Stage 1: isolated piece recognition

### Dataset

The existing 199-row probe contains:

- 172 isolated asset compositions;
- 27 cluttered local board crops;
- tile resource/number, road owner, node occupancy, port type, and robber-presence questions.

Qwen3.8 was run with reasoning disabled and no atlas prompt. The run used unpinned OpenRouter routing: 165 Chutes responses and 34 AkashML responses were persisted directly.

### Overall result

| Scoring policy | Exact | Component |
| --- | ---: | ---: |
| Canonical Catan tokens | 74/199 (37.19%) | 60.00% |
| Resource synonyms only | 111/199 (55.78%) | 70.57% |
| Resource synonyms + BLUE/MYSTIC_BLUE collapse diagnostic | 115/199 (57.79%) | 71.71% |

The resource-synonym policy maps `FOREST→WOOD`, `WOOL→SHEEP`, and `GRAIN→WHEAT`. It is a perception diagnostic, not permission to violate the canonical output contract. `MYSTIC_BLUE` and `BLUE` are distinct engine colors; the four additional matches from collapsing them are reported only as a color-family diagnostic.

Strict canonical scoring splits almost identically by visual context:

| Context | Exact | Component |
| --- | ---: | ---: |
| Isolated assets | 64/172 (37.21%) | 61.11% |
| Local board crops | 10/27 (37.04%) | 52.27% |

## Stage 2: text representation bake-off

### Controlled design

The same 110 question IDs, questions, categories, and expected answers from the prior full-board visual run were reused.

Each of the ten authoritative contracts was normalized into one target-neutral fact object containing:

- all tile IDs, cube coordinates, resources, numbers, and robber flags;
- occupied nodes, with omitted nodes explicitly defaulting to `EMPTY`;
- roads, with omitted edges explicitly defaulting to `EMPTY`;
- all ports, trade types, coordinates, directions, and attached nodes.

Player summaries and precomputed building/road counts were excluded, so count questions still required derivation. Every renderer round-trips losslessly to the same canonical fact object across all ten contracts.

The four inputs were:

1. **Verbose JSON** — descriptive keys and indentation;
2. **Compact JSON** — positional arrays plus a legend;
3. **Graph DSL** — line-oriented typed records;
4. **Spatial ASCII** — tile rows plus readable node, road, and port sections.

Output/scoring was held constant. No image was sent. All 440 requests were pinned to AkashML with fallbacks disabled, temperature 0, and reasoning disabled. Representation order was rotated by question to limit time-order effects.

### Overall result

“Engine exact” below means all expected answer components were present under the established CatanBoardBench scorer; it is neither literal equality nor strict semantic exactness. The scorer generally does not reject extra or contradictory components.

| Representation | Engine exact | Component | Prompt tokens | Cost | Median latency |
| --- | ---: | ---: | ---: | ---: | ---: |
| Spatial ASCII | **93/110 (84.55%)** | **89.45%** | **144,219** | **$0.059382** | **0.83 s** |
| Compact JSON | 87/110 (79.09%) | 87.16% | 162,281 | $0.061846 | 0.88 s |
| Graph DSL | 87/110 (79.09%) | 85.78% | 155,736 | $0.061412 | 0.86 s |
| Verbose JSON | 84/110 (76.36%) | 84.40% | 383,381 | $0.139363 | 1.07 s |
| Prior full-board image | 24/110 (21.82%) | 20.18% | 65,357 | $0.027169 | 2.35 s |

Literal `response == expected` counts were 58 for verbose JSON, 54 for compact JSON, 52 for graph DSL, and 53 for spatial ASCII. Those lower figures primarily reflect punctuation/token presentation accepted by the engine scorer, so they should not be treated as semantic accuracy either.

A post-run audit found one definite semantic false positive inside ASCII's reported 93: for `sample_004_q19_port_occupancy`, the expected occupant was `<N44>`, but ASCII returned both occupied `<N40>` and `<N44>`. Graph DSL made the same error. The component-presence scorer ignored the extra false occupant. Without a complete strict rescore, 93/110 is therefore the historical scorer result and **at most 92/110 strict semantic exact**.

| `color_road_count` | 3/10 | 5/10 | **7/10** | 6/10 | 6/10 |

Spatial ASCII’s six-answer lead over compact JSON is not broad superiority across every task. It is concentrated in node occupancy: the readable `node=color/building` presentation produced 7/10, versus 2/10 for graph DSL and 0/10 for both JSON variants. The question asked only “What building” while scoring also required owner color; ASCII often copied both fields from its `COLOR/BUILDING` syntax, whereas JSON usually returned only the requested building. This is syntax/output alignment, not evidence that the spatial layout helped. The paired 7-win/1-loss difference versus compact JSON also falls short of a conventional two-sided exact McNemar threshold (`p≈0.070`).

All formats solved the direct tile, robber, edge-owner, road-location, and port-type lookups almost perfectly under the permissive scorer. All 40 building-count responses were a single integer because no count-specific answer grammar was supplied. For ASCII, four zero-city cases returned the correct settlement scalar but omitted cities; three mixed-building cases returned building VP; one returned total pieces; and two were numerically wrong. This combines a prompt/output-contract flaw with genuine aggregation/task-selection errors rather than establishing one uniform counting failure.

### Paired outcomes

Across the 110 questions:

- all four formats were correct on 82;
- at least one format was correct on 96;
- all four failed the same 14;
- spatial ASCII uniquely solved five;
- versus compact JSON, ASCII won seven paired cases and lost one.

### Format efficiency

Relative to verbose JSON:

- spatial ASCII used 62.4% fewer prompt tokens and gained nine exact answers;
- graph DSL used 59.4% fewer prompt tokens and gained three exact answers;
- compact JSON used 57.7% fewer prompt tokens and gained three exact answers.

Verbose JSON’s redundancy increased cost without improving accuracy. Compact JSON remains the safer canonical teacher/storage contract because it is directly machine-validatable; spatial ASCII is a strong human/model-facing projection, especially for node bindings.

## Main conclusions

1. **Dense visual grounding is the largest observed gap in this fixed suite.** Giving the same board facts as text raises the best score from 24/110 to 93/110. This comparison is not provider-controlled—the prior image run used mixed routes while text was pinned to AkashML—so the exact delta should not be treated as a pure modality causal estimate.
2. **Primitive perception is also genuinely weak.** Even isolated/local piece crops score 37.19% under canonical tokens and 55.78% after defensible resource-synonym repair. Node color/building recognition remains zero exact.
3. **JSON is viable but verbosity is harmful.** Compact JSON matches graph DSL at 87/110 and costs less than half as much as verbose JSON.
4. **Serialization syntax changes response behavior.** Spatial ASCII’s `COLOR/BUILDING` cells elicited more complete node tuples, but this run does not show that spatial placement caused the gain.
5. **Symbolic state does not eliminate aggregation failures.** ASCII listed the exact road IDs in all ten states yet miscounted four corresponding sets. Building-count responses also reveal an avoidable answer-schema ambiguity that must be fixed before attributing every miss to reasoning.

Recommended architecture: retain compact versioned JSON as the canonical contract, derive a concise spatial/ASCII projection for model consumption or debugging, and treat images as a sidecar rather than the sole state channel until visual grounding is trained substantially further.

This run varied **input board-state formatting**. It deliberately held output/scoring constant. Enforced JSON output is a separate experiment that would primarily measure schema compliance rather than perception.

## Limitations

- The fixed 110-question suite contains ten temporal snapshots from only two replay games; eight snapshots come from one game. Results are paired diagnostics, not population-level format rankings.
- The selected `tile_has_robber`, node, and edge questions are all positive/occupied cases; empty/default handling is not tested. Three robber categories also repeat the same underlying fact.
- Only tiles are spatially arranged. Nodes, roads, and ports are flat records, and no selected question tests direction, adjacency, distance, rotation, or topology. This run must not be cited as evidence of spatial-ASCII competence.
- The component-presence scorer does not generally reject extra values or preserve tuple associations; strict semantic scoring is required for the next run.
- Piece recognition and the prior image benchmark were not provider-pinned to the same route as the text run.
- The text formats expose authoritative symbolic facts by design; they test retrieval/composition, not perception.
- Semantic alias rescoring is diagnostic only. Deployment still requires canonical Catan tokens.
