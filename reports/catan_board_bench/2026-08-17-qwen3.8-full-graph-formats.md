# Qwen3.8-27B full-graph text-format comparison

Date: 2026-08-17

## Executive result

Six lossless text renderings of the same complete public Catan graphs were
compared on the existing strict 60-question suite. The observed ranking was:

1. `tile_rows`: 44/60
2. `full_graph_json`: 41/60
3. `datalog`: 39/60
4. `integrated_ascii`: 38/60
5. `sql_relational`: 36/60
6. `optimized_html`: 35/60

This is **not a statistically established format winner**. A paired Cochran Q
test across all six formats gave `Q=9.970`, `df=5`, `p=0.0761`. No pairwise
exact McNemar result survives correction across the 15 exploratory format
comparisons.

The suite is also **not saturated**. The best format reached only 73.3%, ten
questions defeated every format, occupied-port queries were 0/18, and positive
production queries were 0/18. Do not increase the suite's overall difficulty
yet.

The optimized HTML representation did achieve its efficiency objective. It
used the fewest provider-reported prompt tokens, had the lowest cost, and had
the lowest median and p95 latency, but it traded away nine correct answers
relative to `tile_rows`.

## Design

- Dataset: `data_pipeline/catan_board_bench/datasets/full_graph_format_probe/`
- Source suite: `ascii_variation_probe`, preserved byte-for-byte
- Boards: 12 boards from 12 replay games
- Questions: 60 total, six in each of ten categories
- Formats:
  - compact semantic HTML tables (`optimized_html`)
  - typed scene-graph JSON (`full_graph_json`)
  - model-only Datalog facts (`datalog`)
  - SQL relational DDL and inserts (`sql_relational`)
  - occupation-integrated global ASCII (`integrated_ascii`)
  - incumbent tile-row ASCII (`tile_rows`)
- Incident-list format: excluded
- Images: none
- Worked examples: none
- IDs: opaque, deterministically permuted, and board-local
- Scorer: `strict_typed_json/v2`
- Model: `qwen/qwen3.8-27b`
- OpenRouter provider: exactly `AkashML`
- Provider fallbacks: disabled
- Temperature: 0
- Reasoning: explicitly disabled
- Calls: 360, one per question/format pair

Every format contains the same target-neutral public facts: 19 tiles, 54
nodes, 72 edges, and 9 ports. All 72 board/format renderings parse back to the
same canonical fact digest. No representation contains player summaries,
precomputed counts, or question answers. Named neighbor relations are not
materialized in any format; every format exposes the same cube coordinates.

`integrated_ascii` draws tile state, buildings, and roads in its global spatial
layer. Its appendix contains only static topology and ports. The parser rejects
missing or duplicated dynamic glyph IDs and dynamic glyphs placed outside the
diagram.

Neither Datalog nor SQL was executed to answer questions or exposed solver
output to the model. The integrity parser executes SQL in an in-memory SQLite
database to validate round trips; Datalog is parsed as facts without a logic
engine.

## Admission and integrity

The evaluator revalidated source locks, generated QA/fact files,
representation hashes, parser round trips, scorer hashes, prompt hashes, the
served model, the single pinned provider, and empty reasoning fields. It also
used an exclusive output-directory lock and retained the earliest admissible
response for each pair.

Final run admission:

- 360/360 unique pairs present
- 360/360 successful
- 360/360 valid JSON
- 0 transport or provider errors
- 360/360 served by `qwen/qwen3.8-27b` through `AkashML`
- 0 reasoning tokens
- 0 nonempty native-reasoning payloads
- resume check: `0 pending of 360`
- independently recomputed scores: 360/360 match stored scores

The run used 2,078,130 prompt tokens and 5,664 completion tokens, cost
`$0.91596490`, and had 2.180 s median and 16.151 s p95 latency overall.

## Overall results

The primary measure is strict semantic exactness. “Protocol” is stricter
literal equality with the canonical JSON string and is shown only as a
serialization diagnostic.

|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `tile_rows` | **44/60 (73.3%)** | 24/60 | 12,125 | 409,206 | 6,820 | $0.17720830 | 2.348 s | 16.151 s |
| `full_graph_json` | 41/60 (68.3%) | **26/60** | 12,446 | 331,119 | 5,519 | $0.14989315 | 2.442 s | 18.305 s |
| `datalog` | 39/60 (65.0%) | 20/60 | 13,218 | 394,659 | 6,578 | $0.17324135 | 2.817 s | 12.174 s |
| `integrated_ascii` | 38/60 (63.3%) | 24/60 | 19,647 | 320,541 | 5,342 | $0.14349145 | 1.907 s | 13.243 s |
| `sql_relational` | 36/60 (60.0%) | 20/60 | 10,743 | 367,182 | 6,120 | $0.15739830 | 2.099 s | 24.812 s |

Relative to `tile_rows`, optimized HTML used 37.6% fewer prompt tokens and cost
35.3% less. Its strict accuracy was 15.0 percentage points lower. Compact HTML
therefore remains a useful efficiency endpoint, not the observed accuracy
leader.

On the observed dimensions of exact score, prompt tokens, cost, and median
latency, the nondominated set is:

- `optimized_html`
- `integrated_ascii`
- `full_graph_json`
- `tile_rows`

`full_graph_json` dominates `datalog` on all four dimensions.
`integrated_ascii` dominates `sql_relational` on all four. These are operational
Pareto observations from one run, not general model-capability claims.

## Paired statistics

The unit of pairing is the same question over the same board facts.
Representative exact two-sided McNemar comparisons were:

| Comparison | First-only wins | Second-only wins | Raw p |
|---|---:|---:|---:|
| `tile_rows` vs `full_graph_json` | 7 | 4 | 0.549 |
| `tile_rows` vs `datalog` | 9 | 4 | 0.267 |
| `tile_rows` vs `integrated_ascii` | 9 | 3 | 0.146 |
| `tile_rows` vs `sql_relational` | 9 | 1 | 0.0215 |
| `tile_rows` vs `optimized_html` | 11 | 2 | 0.0225 |
| `full_graph_json` vs `optimized_html` | 6 | 0 | 0.0313 |

The last three raw p-values are exploratory. None remains significant after
accounting for all 15 pairwise comparisons, and the omnibus Cochran test is
itself above 0.05. The numerical ranking should not be promoted to a universal
format ordering.

These are nominal item-level p-values. Cochran Q uses its asymptotic chi-square
reference distribution. Both Q and McNemar treat the 60 questions as
independent units, although questions share 12 boards and were deliberately
selected by category. No board-clustered or repeated-run inference was
performed.

The incumbent also showed useful stability. The earlier ASCII run scored
`tile_rows` at 44/60; this run again scored it at 44/60, with 58/60 question
outcomes unchanged. This is a representation-level near-replication, not a
byte-identical prompt repeat. The tile-row files are unchanged, but all prompt
hashes differ because the generic system framing, null/count wording, format
label, and graph-boundary wrapper changed.

## Error localization

### Question-level ceiling and floor

Across the six formats:

- 27/60 questions were correct for all six formats.
- 10/60 questions were wrong for all six formats.
- 23/60 questions produced at least one format disagreement.

The universal failures were two direction→tile questions, two tile→direction
questions, all three occupied-port questions, and all three positive-production
questions.

### Port occupancy

- Occupied ports: 0/18 across formats.
- Empty ports: 15/18 across formats.

The same failure mode persisted across syntax families: responses commonly
retained the correct occupied tuple but also emitted the empty endpoint, or
missed the occupied endpoint. This is a filtering/join diagnostic, not evidence
that a particular punctuation style cannot express ports. A focused rerun
should explicitly say “include occupied nodes only; omit empty endpoints.”

### Production

- Positive production: 0/18.
- Empty production: 6/18.

The model still failed the full procedural chain: roll matching, robber
filtering, tile-corner joins, occupied-node filtering, city weighting, and
aggregation. Datalog and SQL did not solve this when interpreted by the model
alone. A solver-backed logic or SQL condition would be a different experiment.

### Direction

`integrated_ascii` was numerically best on the two direction categories at
7/12, followed by `tile_rows` at 6/12. That small advantage did not generalize
to overall accuracy.

Both inverse `UP-RIGHT` and inverse `DOWN-RIGHT` questions were wrong in all six
formats, while the selected inverse `UP-LEFT` and `DOWN-LEFT` questions were
correct in all six. Full-context endpoint errors still do not localize whether
record lookup, coordinate extraction, subtraction, convention mapping, or
layout reading failed.

### Counts and inventories

Building counts reached 27/36; full-graph JSON alone was 6/6. Road inventories
reached 28/36, but the easy cases conceal the hard cases:

- zero-road and one-road questions: 24/24;
- dense six-road RED question: 1/6;
- four-road BLUE question: 3/6.

Future count questions should continue requiring both source IDs and counts so
internal inconsistency remains visible.

### Integrated occupation

Drawing roads and buildings into the global ASCII layer did not create a broad
accuracy gain. It helped some direction items but lost direct lookup and
aggregation items relative to the incumbent. This run does **not** isolate a
causal spatial-grounding effect because `integrated_ascii` and `tile_rows` are
not length- and redundancy-matched controls.

## Decision

Do not make the broad 60-question suite harder yet. Freeze it as `v1` for
replication and use focused diagnostics to make the current failures
interpretable.

For the next broad format comparison, retain the observed Pareto set:

- compact HTML as the efficiency endpoint;
- integrated ASCII as the occupation-integrated spatial candidate;
- full-graph JSON as the strongest compact structured candidate;
- tile rows as the incumbent accuracy baseline.

Do not spend another broad run on Datalog or SQL unless testing a specific
logic-oriented hypothesis. If either is paired with deterministic execution,
label that as a separate solver-backed condition rather than a serialization
result.

Before increasing difficulty:

1. Run the staged direction ladder: record lookup, coordinate extraction,
   subtraction, direction mapping, local layout, hybrid local, then full board.
2. Decompose production into roll selection, robber filtering, corner lookup,
   occupied-node filtering, city weighting, and aggregation.
3. Compare zero-shot against worked ICL on production; the current run is
   zero-shot contextual parsing.
4. Rerun occupied ports with an explicit occupied-only instruction.
5. Add a truly length-matched nonspatial repetition control before attributing
   any gain to integrated geometry.
6. Repeat the leading formats before claiming a small ordering difference.

A practical gate for a harder broad suite is at least two runs with a leading
format at or above 90% strict overall and no category below 80%. This run is
well below that gate.
